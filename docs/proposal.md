# dongxiv 建站计划（Proposal）

> 状态：阶段 1 已完成（本地原型） · 最后更新：2026-11-26
> 标记说明：✅ 已确定 · ❓ 待定（需要讨论）

---

## 1. 背景与目标

在别人的平台上发文章流程繁琐、受人限制。我们要建一个**只属于自己的 arXiv 式论文存档站**，用来发布自己的 *vibe research* 文章（人提出问题、想法并做判断，AI 深度参与探索、计算和写作）。

**目标**

1. **发布要省事**：拖入 PDF、填好表单、点"发布"，几分钟后上线。
2. **编号永久**：每篇论文有永久编号和固定网址，可以被引用。
3. **版本透明**：每个版本都公开发布时间和 PDF 的 SHA-256 哈希。
4. **说明 AI 的参与**：每篇论文写清人和 AI 的分工以及验证状态。
5. **观感对标 arXiv**：学术圈的人一眼就知道怎么用，但不使用 arXiv 的品牌元素。

**非目标（暂不做）**

- 接收别人的投稿、审核、用户账号
- 评论区、按下载者打 PDF 水印
- 公开 TeX 源码、HTML 版全文

**参考**

- arXiv 的列表页和摘要页
- [liuxiv](https://jihaoliu.org/liuxiv.html)：个人版 arXiv，编号格式为 `liuxiv:YYMM.NNNN`，记录 AI 参与情况和验证状态，每个版本公开 SHA-256

## 3. 总体架构

```
 ┌─────────────── 你的电脑 ───────────────┐
 │                                         │
 │  本地管理后台 (localhost)               │
 │   拖入 PDF / 填表 / 预览 / 点"发布"     │
 │            │ 写入文件                    │
 │            ▼                             │
 │  papers/2612.0001/meta.yaml, v1.pdf …   │
 │            │ git commit + push           │
 └────────────┼────────────────────────────┘
              ▼
       GitHub 公开仓库
              │ 自动触发
              ▼
        Vercel 构建
  （元数据 → 静态 HTML 页面、
     搜索索引、RSS、sitemap）
              │
              ▼
     https://<域名>/  （CDN 分发）
```

- **唯一的真实数据**：仓库中的 `papers/` 目录，网站上的所有页面都由它生成。
- **没有服务器端代码，也没有数据库**：线上只有静态文件，安全，零运维。
- **管理后台只在本机运行**：不对外暴露，所以不需要做登录和权限。

## 4. 编号与版本规则

- **编号格式**：`dongxiv:YYMM.NNNN`
  - `YYMM` 是第一版发布时的年月（UTC）。
  - `NNNN` 是当月的序号，从 `0001` 开始。
  - 例：`dongxiv:2612.0001`
- **版本号**：`dongxiv:2612.0001v2`。不带版本号的编号永远指向最新版本。
- **固定网址**：

  | 内容 | 网址 |
  |---|---|
  | 摘要页（最新版） | `/abs/2612.0001/` |
  | 某个版本的摘要页 | `/abs/2612.0001v1/` |
  | PDF（最新版） | `/pdf/2612.0001.pdf` |
  | PDF（指定版本） | `/pdf/2612.0001v1.pdf` |

- **不可变规则**
  - 已发布版本的 PDF **永远不能替换**，有修改就发新版本。
  - 每次构建都会重新计算哈希并与记录比对，不一致就报错，拒绝发布。
  - 标题、摘要、备注等元数据可以修改，Git 历史会记录每次改动。
- **撤稿**：不删除，只把论文标记为 withdrawn，摘要页显示撤稿说明，原有链接继续有效。arXiv 也是这样处理的。

## 5. 数据结构

### 5.1 目录

```
papers/
  2612.0001/
    meta.yaml        # 元数据
    v1.pdf
    v2.pdf
  2612.0002/
    ...
site.toml            # 站点配置（名字、作者、域名、是否允许收录……）
```

### 5.2 元数据示例（`meta.yaml`）

```yaml
title: ...
authors: [Dong]
abstract: |                   # 支持 $数学公式$，空行分段
  ...
comments: 12 pages, 3 figures # 支持 [文字](链接)
primary_subject: ...
subjects: [...]
keywords: [...]
license: CC BY 4.0            # 不写则用站点默认
links:
  - { label: Code, url: "https://..." }
withdrawn: ...                # 写了就表示已撤稿，内容是撤稿说明

vibe:                         # 每一项都可省略，省略的不显示
  human_role: Problem, key ideas, final checking
  agents: [Claude Code]
  models: [Claude Opus 5.5]
  machine_verified: "yes"     # "yes" / "no" / partial / 省略（未说明）
  human_verified: partial
  formal_verified: "no"       # 例如 Lean 形式化
  materials:
    - { label: Transcript, url: "https://..." }
  notes: ...

versions:                     # 由后台自动生成，不要手改
  - date: "2026-12-01T08:00:00Z"
    file: v1.pdf
    sha256: ...
    pages: 12
    note: ...                 # 本版本的修改说明
```

**Vibe research 字段**：四类全部预留，没填的项不显示。验证状态是作者自己的声明，About 页说明了每个标记的含义。以后可以按研究领域再细化。

## 7. UI 设计原则

| 沿用（学术惯例和信息结构） | 不用（arXiv 品牌元素） |
|---|---|
| 按日期分组的列表、条目格式 | arXiv 的红色顶栏 `#b31b1b` → 换成深蓝 `#26456e` |
| 摘要页字段的顺序、右侧边栏 | arXiv 的 logo、Cornell 和 Simons 等致谢条 |
| `YYMM.NNNN` 编号 + `vN` 版本号 | 页面文案不照抄（例如不用 "Submitted on"，改用自己的说法） |
| 简洁、信息密集的风格 | 字体和细节样式自己定（例如标题用衬线体） |

## 8. 发布后台（本地 UI）

**启动**：在终端运行一条命令，浏览器自动打开 `http://localhost:xxxx/admin`。

**功能**

1. **发布新论文**
   - 拖入 PDF，自动读出页数、计算 SHA-256。
   - 填写表单：标题、作者、摘要（实时预览公式）、学科、vibe 字段等。
   - 系统自动分配下一个编号。
2. **发布新版本**：选择一篇已有论文，拖入新 PDF，填写修改说明。
3. **修改元数据**：编辑标题、摘要等。已发布的 PDF 不能替换。
4. **预览**：按线上效果渲染整站，确认后再发布。
5. **发布**：一键完成 `git commit` 和 `git push`，Vercel 自动部署，页面显示部署进度和最终链接。
6. **撤稿**：把论文标记为 withdrawn，并填写撤稿说明。

**安全措施**

- 后台只监听本机地址（127.0.0.1），网络上的其他设备访问不到。
- 后台代码不会被部署到线上。

**在线后台**（2026-11-26 加）：`https://dongxiv.vercel.app/admin/`，用 GitHub 登录（只限仓库主人），在浏览器里直接通过 GitHub API 提交，Vercel 自动部署。见 [online-admin.md](online-admin.md)。

## 9. 可信度与永久性

自建平台的弱点是：别人凭什么相信你的发布时间？我们用几层证据互相印证：

1. **页面上公开哈希和时间**：每个版本公开 SHA-256 和 UTC 时间戳。
2. **公开的 Git 历史**：每次发布对应一个公开的 commit，时间记录在 GitHub 上，任何人都能查。
3. **区块链时间戳（可选）**：用 OpenTimestamps 把哈希锚定到比特币区块链，免费，事后无法伪造。
4. **第三方快照（可选）**：每次发布后自动提交给 Internet Archive，留一份别人可查的快照。
5. **DOI（可选）**：重要论文同步一份到 Zenodo，获得 DOI。

**备份**：本地文件夹 + GitHub + Vercel 上的部署，共三份。

## 10. 技术选型 ✅ Astro

| 部分 | 方案 A：Astro | 方案 B：Python 脚本 |
|---|---|---|
| 生成网站 | Astro 静态生成；用 schema 校验元数据（格式出错时构建直接失败） | Python 标准库脚本，没有任何依赖 |

| 适合谁 | 熟悉 JS/TS 生态 | 熟悉 Python |

**已选方案 A（Astro 7）**：Vercel 官方支持；页面模板接近 HTML，以后调整 UI 方便。元数据用 YAML（比 TOML 更适合 JS 生态），用 zod 校验格式。

## 11. Google Scholar 收录 ❓

**是否开放收录**：待定，在 `site.toml` 里用一个开关控制。

**如果开放，需要满足**

- 每篇论文有独立的摘要页，页面里带 `citation_title`、`citation_author`、`citation_publication_date`、`citation_pdf_url` 等 meta 标签。构建时会自动生成。
- PDF 是可提取文字的，第一页清楚显示标题和作者。LaTeX 编译出来的 PDF 天然满足。
- robots.txt 允许抓取，PDF 不需要登录或点击就能访问。
- PDF 文件不要太大。

Scholar 没有申请入口，只能等爬虫来抓，一般要几周到几个月，也不保证一定收录。

## 13. 风险与对策

| 风险 | 对策 |
|---|---|
| 编号或网址规则改动，导致已发出的引用失效 | 第一篇真实论文发布前定死；以后迁移只换后端存储，网址不变 |
| 已发布的 PDF 被误替换 | 构建时校验哈希，不一致直接失败 |
| 仓库越来越大 | 预计每年约 150 MB；超出 Vercel 限制前把 PDF 迁到 Blob |
| Vercel 免费版的限制（非商业用途、部署体积） | 个人学术用途符合要求；上线前核对 Limits 文档 |
| 因为没有第三方背书，发布时间被质疑 | 用 §9 的多层证据 |
| 对标 arXiv 时撞上它的品牌 | 遵循 §7 的原则 |
| 仓库公开，私人材料或密钥被意外提交 | TeX 源码和私人材料不放进本仓库；`.gitignore` 排除 `.env`；每次提交前检查 |
